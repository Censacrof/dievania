# Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 24-cell board: every rolling player action moves a token by the roll total, and the landed cell modifies that action or grants a bonus.

**Architecture:** The board is data (`content.BOARD`) copied into `GameState.board`; `GameState.position` persists across fights. `playerAction` moves the token right after rolling and applies the cell's modifier while resolving. The UI renders the board as a strip inside the player card with a popover per cell.

**Tech Stack:** TypeScript engine, Vitest, React 19 UI. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-13-combat-prototype-design.md`, section "The Board".

## Global Constraints

- English everywhere. TDD red → green → refactor per task.
- All paths relative to `combat-prototype/`; run commands there.
- RNG consumption order inside `playerAction` stays: player rolls (Lucky reroll inline) → Echo draws → Fortune draw → offers/encounter load. The board move itself consumes no rng.
- Existing tests rely on `newGame(zero)` starting at position 0; two tests whose rolls now land on Critical must start from position 1 instead (see Task 2).
